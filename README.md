# JomiJachai (জমিযাচাই)

**Stop land fraud before it happens.** JomiJachai checks every land sale against six rules *before* the deed is registered, and lets anyone verify a deed with one phone tap, in Bangla.

LandTech Innovation Hackathon 2026 · Track: Digital Land Records, Verification & Digitization
Problem: **P3, Catch Fraud & Double-Selling**. The prototype also covers P2 (verify deeds) and P5 (check before you buy). P4 (smart e-mutation) is the next phase.

> **All data in this app is fictional.** No real land records, names, NID or phone numbers are used, and nothing is taken from government websites.

## What works in the Round 1 prototype

| Feature | Where |
|---|---|
| **Six-rule checker** runs behind the scenes when a sale application is submitted; the officer sees only the result (approved, refused with the reason, or warnings to review) | Officer Portal → Register a sale |
| **Share register**: how many decimals each owner still holds in each dag, stored as exact fractions | Officer Portal → Plots & shares |
| **Deed with SHA-256 fingerprint and QR code**, printable | Officer Portal → Deeds |
| **Append-only activity log**: every check, approval and blocked attempt, chained by SHA-256 so any edit is detectable | Officer Portal → Activity log |
| **Check land before buying**: search a dag number (the mouza is optional) and the **map marks that dag and its location** with a pin and a **card listing all its warnings**; switch between satellite, street map and **Google Maps**, or tap a dag on the map → owners, decimals, and one answer (safe / be careful / risky) with a **Read aloud** button (Bangla voice: the phone's own when it has one, otherwise an online Bangla voice) | Citizen App → Check land |
| **Verify a deed**: scan its QR, compare the paper with the official record → genuine, altered copy, or fake QR | Citizen App → Check a deed |
| Bangla first, English toggle, light and dark theme | Everywhere |
| Installable phone app (PWA), works offline after the first visit | Citizen App |

### The six rules

| # | Rule | If it fails |
|---|---|---|
| 1 | Seller is a recorded owner of this dag | ❌ Block |
| 2 | Decimals sold ≤ seller's remaining share | ❌ Block (over-selling or double-selling) |
| 3 | No open court case on the plot | ❌ Block |
| 4 | Not khas land and not under acquisition | ❌ Block |
| 5 | Not mortgaged to a bank | ⚠️ Warning |
| 6 | Not resold within 30 days | ⚠️ Warning |

Code: [`lib/register.js`](lib/register.js) → `checkSale()`.

## How it works

- **One app, two screens.** One Next.js website. The *Officer Portal* (`#officer`) is for Sub-Registry and land offices on a computer. The *Citizen App* (`#citizen`) is the phone app for buyers and villagers. Both use the same checker and land register.
- **Exact shares.** Shares are stored as fractions (`"1/3"`), never rounded, so a 2-decimal plot shared by six heirs still adds up to exactly 2. See [`lib/fraction.js`](lib/fraction.js).
- **Digital fingerprint.** On approval, the deed's details are joined in a fixed order (`deed no | mouza | JL | dag | seller | buyer | decimals | date`) and turned into a 64-character SHA-256 code ([`lib/sha256.js`](lib/sha256.js), using the browser's Web Crypto API). The code goes into the Deeds table and into the deed's QR code. Changing one digit changes the whole code.
- **Verifying.** The QR holds a link: `…/#v-<deed no>-<fingerprint>`. Opening it recalculates the fingerprint from the official record. If the QR's code is different → **fake QR**. If it matches, the app shows the official record and asks what the paper says → **genuine** or **altered copy**.
- **Scanning a QR.** In-app scanning uses the browser's BarcodeDetector (Chrome on Android). On other phones, scan with the normal camera app: the QR is a link that opens the verification screen directly.
- **QR codes** are generated by our own small encoder ([`lib/qr.js`](lib/qr.js)), with no external library.
- **Activity log.** Each entry stores the previous entry's hash, like a chain. Changing an old entry breaks the chain, and the log page shows it.

### Data storage: two backends behind one API

Every screen reads and changes the land register only through one API (`lib/api/`). The six rules always run in `lib/register.js`; the API hands each change to one of two backends:

- **This browser (default, no setup).** The register is saved in each device's browser (localStorage). To show the same register on a laptop and a phone during the demo, open **Officer Portal → Sync to phone** and scan that QR with the phone.
- **Shared database (Supabase / PostgreSQL).** Switches on by itself when two Supabase keys are set. The laptop and the phone then share one register, and a new deed appears on the phone without the sync QR. The database itself refuses any edit or delete of deeds and log lines, and checks the log's hash chain. Setup takes about 10 minutes: see [`supabase/README.md`](supabase/README.md).

The footer and the Officer Portal show which backend is in use.

### Google Maps view (optional)

The land map works without any setup: satellite photo and street map, and every searched dag gets a pin, a white outline and a card with its warnings, at every zoom level. A **Google** view (the same outlines and pin on Google's own map) appears when a Google Maps API key is set:

1. Go to [console.cloud.google.com](https://console.cloud.google.com), create a project, and turn on **Maps JavaScript API** (Google asks for a billing card; the monthly free usage is far more than a hackathon needs).
2. **APIs & Services → Credentials → Create credentials → API key.** Under **API restrictions**, choose **Restrict key → Maps JavaScript API**. Leave **Application restrictions** on **None**: the site sends no "Referer" header (needed for the Bangla voice), so a website restriction would block the map. Set a daily quota under **Quotas** to be safe.
3. Put the key in `.env.local` (and in your hosting provider's environment variables) as `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`, then build again.

Without a key there is no in-app Google view (Google's free embed cannot draw the dag outlines, so a zoomed-in view showed nothing useful); the dag card's **Open in Google Maps** link opens the spot in the Google Maps app instead.

## Run it on your computer

You need **Node.js 22 or newer** (download from nodejs.org).

```bash
npm install
npm run dev
```

Open http://localhost:3000. To test on a phone on the same Wi-Fi, open `http://<your computer's IP>:3000` on the phone.

Build the static website (written to the `out/` folder):

```bash
npm run build
```

**Install on a phone:** once the site is online, open its link in Chrome on Android → menu (⋮) → **Add to Home screen**. It then opens like an app, starting on the Citizen App.

## Project structure

```
app/                 Next.js App Router: layout (fonts, PWA manifest), page, global styles and design tokens
components/
  App.jsx            Screen switching by URL hash, language and theme settings, loading the register
  Landing.jsx        The website: hero with plot search, result slip, services, deed check, questions
  PlotSlip.jsx       A plot's answer printed like a porcha slip (used by the website and the Citizen App)
  LandMap.jsx        Real map (Leaflet satellite/street view, or Google Maps) with every dag drawn on it; pin and warnings card for the searched dag
  brand.jsx          Logo, date strip (Bangla calendar), language/theme toggles, share bar, QR, demo reset
  ui/                shadcn/ui components (all of them, added with `npx shadcn@latest add --all`)
  officer/           Officer Portal: RegisterSale, Plots, Deeds (deed paper + QR), ActivityLog, Statistics (admin only), SyncPhone, NextPhase
  citizen/           Citizen App: CheckLand, CheckDeed (QR scan + compare), Help
lib/
  api/               The register API: core.js, local.js (browser), supabase.js (shared database), index.js
  register.js        Land register, six-rule checker, deeds, verification, append-only log, demo sync
  seed.js            The fictional register data (58 dags, owners, earlier deeds, history; generated once, written out as plain data)
  fraction.js        Exact fractions for shares
  sha256.js          SHA-256 (Web Crypto, with a pure-JS fallback)
  qr.js              QR code generator
  bangla-date.js     Bangla calendar date for the top strip
  speech.js          Read aloud: device Bangla voice, else an online Bangla voice; Bangla digits; sentence by sentence
  store.js, i18n.js, nav.js
supabase/            schema.sql (tables, append-only rules, hash-chain check) and setup steps
public/              PWA manifest, service worker, app icons, photos (credited in the site footer)
```

**Tech stack:** Next.js, React, Tailwind CSS, shadcn/ui (Radix, lucide icons), Progressive Web App, SHA-256 via Web Crypto API. Data: in the browser by default, or a shared Supabase (PostgreSQL) database when its keys are set. Hosting: static website, deployed from this GitHub repo.

**Logo:** a pin on a mouza map (faint field boundaries) marking one checked dag (lime plot with a tick), on ministry green. Files: `public/icons/icon.svg` (master), app icons in `public/icons/`, the link-sharing image `public/og.png`, and a brand board for slides in `assets/brand/brand-board.png`.

**Design:** modelled on the look of the Ministry of Land's Bhumi Seba portals (green date strip, service tiles, green-header tables), with JomiJachai's own name and logo and no government emblems. It is not a government website. Photos: Wikimedia Commons, credited in the site footer (`assets/credits.json`). Map: [Leaflet](https://leafletjs.com) (open-source), satellite imagery © Esri/Maxar/Earthstar Geographics, street map © OpenStreetMap contributors, and the Google Maps embed, credited on the map itself. The map is real; the dag outlines and their places on it are made up, like all the demo data.
